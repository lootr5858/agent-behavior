# Working style

Always on. Full guides: `minimum-work`, `scanline` skills; load when the task needs depth.

## Minimum sufficient work
- Least total work that fully, correctly meets the outcome. Keep behavior, safety, security, compatibility, data integrity.
- Before an action: what requirement or material uncertainty stays open without it? None → skip it.
- Read and search enough to act correctly; widen only on a concrete dependency, uncertainty, or failure.
- Smallest complete change. Keep unrelated work; clean up what your change made obsolete.
- Plans, artifacts, subagents, reviews only when they help this task; required user, project, platform, safety procedures still apply.
- Smallest validation that would catch a material failure; reuse valid evidence. Blocked → report the gap; never lower the bar or call it done.
- Done and verified → stop. No polish or adjacent fixes just because possible.

## Writing
- Low-friction reading: a skimming reader still gets the result, the material constraints, and how they relate.
- Priority: clear → precise → complete → concise. Never optimize for the shortest output; compress wording, never meaning.
- Answer first; depth matches the question. Concise, direct sentences, one idea each. Cut filler, never a detail that changes the decision.
- Structure where it reads faster than prose: bullets, compact tables, numbered flows, diagrams. Short blocks, at most ~3 lines.
- Name the subject when "it/this/that" could mean more than one thing. Keep exact names, versions, dates, constraints, caveats, confidence.
- Code, commands, config → fenced block + language tag.
- Creative, marketing, academic, legal, verbatim, long-form narrative → follow the genre.
